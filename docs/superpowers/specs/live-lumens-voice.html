Live Lumens and the narrator

One live voice, the copilot speaking, that the learner can reach from anywhere in the app. It narrates a Lumen and lets the learner cut in at any point. It answers questions in the middle of a recorded Lumen. And it acts on the graph and the library under the same rules as the text copilot.

01 · The framework

Where does the conversation live?

Everywhere, one session at a time. The session belongs to the app shell rather than to any one page, so it carries on while you navigate, like the Graph's “Now playing” dock does today. It always has an anchor: the thing the conversation is about. Each surface does three jobs. It offers a way in with a sensible anchor, it keeps the narrator updated on what's on screen, and it receives the results where they belong.

Session ≠ connection

ElevenLabs bills every minute a connection is open, silence included. So when the learner says “stop”, or after 30 seconds of quiet, the connection closes. The session keeps the anchor, the position in the deck, the transcript and any pending cards. Resume opens a new connection seeded with that state.

Every ending makes a recap

A session ends when the learner says “that's all” or presses End, after an idle timeout, at the cap, or when the Lumen finishes. Then a Recap card shows what we covered, what was saved, what changed (with Undo), the suggestions still waiting, and “pick up here”, which feeds Today's Continue card.

02 · Build order

Three levels, one assistant

L1

Ask the Lumen

Any recorded Lumen can be interrupted. The recording pauses and the narrator answers from the slide on screen, sometimes sketching a quick board slide. Then the recording resumes where it stopped.

New generation work: none · works on every existing Lumen
L2

Live Lumen

The narrator performs the Lumen live. The learner can cut in any time with “another way”, “deeper”, “skip”, “back” or “test me”, and the beat is rewritten in about 6 seconds.

New: explainer_beat rework call · live driver
L3

Narrator actions

The same voice proposes map changes, sorts the library, suggests what to learn next and starts Lumens or courses, always with Propose → Confirm → Undo.

New tools: read_library · propose_library_plan · suggest_next · navigate · capture_note
03 · Live Lumens

A Live Lumen is a Lumen whose say lines are performed live

Contract 1.4 already gives a live deck everything it needs: ordered <item> slides, <say> speaker notes, [[s3.anchor]] pointer refs, checked citations and two follow-ups. So the new part is not the content type. It is only who voices the say lines. With generateQuick(…, voice:"live"), the author run skips the per-line TTS jobs and the narrator performs each line instead. Afterwards the deck is an ordinary Lumen in Learn. The author still writes slide and narration together, which avoids the “splitting writer and drawer loses quality” trap (AI Lab E25–27).

0 s

Talk starts at once

The narrator frames the topic and asks one warm-up question while the author writes. The answer goes to the author as a focus hint.

≈ 3–8 s

Board slide

An instant title or list slide that the narrator draws itself from simple types only. It is never cited. This is FS-3's instant title card.

≈ 26 s

First authored beat

It arrives over the existing Trigger Realtime stream. If the narrator reaches the ready edge first, it asks a check question.

Try an interruption

Pick something the learner says during beat 3. The trace shows what the system does in response. This is an illustration, not a live demo.

Design rules

  1. All tools are client tools. They act on the UI or call Studiolo with the learner's own session. The model can only do what the learner's UI can do.
  2. One registry. Voice calls the same tool implementations as the text copilot: same action kinds, same 8 KB cap, same read-back strings.
  3. The brain moves home in Phase 2. The custom LLM path runs through callModel, which brings back the 1-hour cache, usage rows, evals and the EU-controlled prompt.
  4. Voice turns are copilot messages, stored with channel='voice'. Voice is an input method (A7).
  5. Swappable transport. OpenAI Realtime, Gemini Live or a DIY Scribe → Claude → TTS pipeline can replace ElevenLabs.

Confirming by voice

Read · navigate · showjust do it
Keep ghost topics / notesvoice yes
Graph / library plan ≤ 5 stepsvoice yes + card ≥1.5 s
Start a Lumen / coursevoice yes after cost said
Merge · delete · plans > 5 stepstap only

The guard runs in the client, not in the prompt. If the card wasn't visible, or there was no explicit yes, the tool returns “needs a tap”.

06 · Cost (estimates; P0 measures them)

Roughly a dollar for a live six minutes

L1 · 2-min question$0.20–0.45

Agent minutes plus the LLM

L2 · 6-min Live Lumen, 2 reworks$0.75–1.60

For comparison: a recorded 3-minute Lumen's voice alone is estimated at $0.65–0.80

L3 · 3-min library sort$0.30–0.70

Most of it is minutes

Inputs: ElevenLabs Agents at $0.08 per minute beyond the plan's included minutes, plus the LLM passed through at roughly $0.02–0.15 per minute (prompt caching decides where in that range). A rework costs $0.02–0.05 and an author run about $0.13 with no TTS. 20 testers × 60 minutes is about 1,200 minutes, close to what the Pro plan includes and within its 20 concurrent calls. Confirm the price on the live pricing page before deciding. Spend cap: a new voice_session start with a per-minute hold, settled by the post-call webhook.

07 · Prototype

Built in Studiolo_Manage, against fixtures, with a $40 cap

A standalone Next.js app at prototypes/live-lumens/. It uses one exported Lumen, a mock map and a mock library, with real ElevenLabs Agents and real Claude. It never touches studiolo. The port into the main app is a separate HIGH-tier spec.

P0 · 2–3 days

Ask the Lumen

Audio driver, Ask / hold Space, board slides. Exit: first word ≤ 1.2 s at p50, barge-in ≤ 300 ms, real cost per minute.

P1 · 4–5 days

Live Lumen

Live driver, warm-up question, rework, cue-word pointer, pause by disconnecting. Exit: rework ≤ 6 s, pointer right ≥ 80% of the time.

P2 · 4–5 days

Narrator actions

Map and library plans, suggest next, confirm guard, recap. Exit: 20 scripted utterances pass, no change applied without the guard.

P3 · 1–2 days

Port spec

VOICE_ACCESS switch, migrations, the voice_session cap, /api/voice/*, an ai.md update, evals. Owner approval.
